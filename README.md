# QR Plate — Autodesk Fusion add-in

Generate printable, two-material QR code plates from a dialog inside Fusion.
Type in a Wi-Fi password (or a contact card, map pin, calendar event, or any
text), press OK, and get two aligned bodies ready for multi-material
printing: a solid `Base` and a raised `Code` layer.

![QR plate generated by the add-in](docs/example-plate.png)

## Features

- **Nine content types**, each with its own dialog fields:
  Wi-Fi network · contact card · phone call · text message · email ·
  map location · calendar event · payment/crypto URI · plain text
- **Optional title text** raised in the same layer as the code, built from
  real font outlines (no Fusion SketchText dependency — see [Notes](#notes))
- **One print-in-place solid** — the raised code sits in its own Z band
  above the base, so a filament change at the base thickness prints it in a
  second color; no assemblies, no aligning meshes
- **Live feedback** — the dialog reports the QR grid and module size and
  warns when a long payload makes modules too small to print reliably
- **Fully parametric** — plate width, thicknesses, corner radius, rim
  chamfer, quiet zone, and error-correction level
- **Remembers your input** — values are stored in the document, so rerunning
  the command pre-fills what is currently encoded and rebuilds in place
- **Self-contained** — pure Python, no `pip install` step

## Installation

### Option 1 — download a release (recommended)

1. Download `QRPlate.zip` from the
   [latest release](https://github.com/jtcressy/fusion-qr-plate-addin/releases/latest).
2. Unzip it into your Fusion add-ins folder, so the folder `QRPlate` sits
   directly inside `AddIns`:
   - **macOS**: `~/Library/Application Support/Autodesk/Autodesk Fusion 360/API/AddIns/`
   - **Windows**: `%APPDATA%\Autodesk\Autodesk Fusion 360\API\AddIns\`
3. Restart Fusion, or press <kbd>Shift</kbd>+<kbd>S</kbd>, select
   **QRPlate** on the **Add-Ins** tab, and click **Run**.

### Option 2 — clone the repo (for updates via `git pull`)

```bash
# macOS
cd ~/Library/Application\ Support/Autodesk/"Autodesk Fusion 360"/API/AddIns
git clone https://github.com/jtcressy/fusion-qr-plate-addin.git QRPlate
```

```powershell
# Windows (PowerShell)
cd "$env:APPDATA\Autodesk\Autodesk Fusion 360\API\AddIns"
git clone https://github.com/jtcressy/fusion-qr-plate-addin.git QRPlate
```

The folder **must** be named `QRPlate` — Fusion requires the add-in folder,
`.py`, and `.manifest` to share a name.

Then enable it: <kbd>Shift</kbd>+<kbd>S</kbd> → **Add-Ins** → **QRPlate** →
**Run** (tick **Run on Startup** to load it automatically).

## Usage

**SOLID** → **Create** → **QR Code Plate**

1. Pick a **Content** type and fill in its fields.
2. Optionally add **Title** text shown under the code.
3. Adjust **Plate** dimensions if needed.
4. Tick **Preview** to build it in the viewport without closing the dialog.
5. **OK** builds a single `QR Plate` body.

Preview is off by default and rebuilds on every input change while ticked, so
fill the fields first, then tick it.

To print in two colors, export the body as a mesh and add a filament change
at the base thickness (default 4.2 mm) in your slicer — everything above it
is the code and title.

Rerun the command in the same document to edit what is encoded — it replaces
the existing plate rather than adding a second one.

### Tips

- **Module size drives scannability.** Aim for ~0.8 mm or larger; the dialog
  warns below that. Longer payloads need a bigger plate.
- **Test-scan before printing.** Click **TOP** on the view cube and set the
  display to **Shaded** (no visible edges) — the raised code is painted black
  against a white plate, so a phone reads it straight off the screen. The
  default isometric view outlines every module in grey and rarely scans.
- **Contact cards with a photo URL** switch from MECARD to vCard 3.0 and get
  noticeably larger — plan on a ~55 mm plate or wider.
- **Images cannot be embedded.** QR capacity tops out around 2–3 KB, far
  below any usable photo, so the photo field takes a URL.
- **Print orientation**: flat on the bed, code side up, with the base as the
  first material. A 0.8 mm raised layer is about 4 layers at 0.2 mm.

## Development

The add-in has no build step. Edit the source, then restart it from
<kbd>Shift</kbd>+<kbd>S</kbd> (**Stop**, then **Run**). Fusion caches an
add-in's entry module across a restart, so `QRPlate.py` is a stub that
reloads everything else — keep it that way and any edit takes effect on
restart.

| File | Responsibility |
| --- | --- |
| `QRPlate.py` | Entry stub — reloads and starts `ui.py` |
| `ui.py` | Command definition, dialog, event handlers |
| `payloads.py` | Builds the encoded string for each content type |
| `qr_plate_core.py` | Fusion geometry: base, QR modules, title text |
| `text_outline.py` | Glyph outlines → polygons with hole detection |
| `truetype.py` | Minimal TrueType parser (cmap/glyf/loca/hmtx) |
| `lib/segno` | Vendored QR encoder ([segno](https://github.com/heuer/segno)) |

Payload building is Fusion-independent and covered by tests that round-trip
every content type through a real QR encode/decode:

```bash
python3 tests/test_payloads.py
```

## Notes

**Why the add-in parses fonts itself.** Fusion's `SketchText` API produces
empty geometry in current builds (verified on 2704.1.36, macOS): created text
has a zero-size bounding box, generates no profiles, and `explode()` returns
nothing, so extruding it fails. Rather than ship a broken title feature, the
add-in reads glyph outlines directly from a system TrueType font and builds
them as BRep faces. This also means titles render identically on machines
where Fusion's text tooling misbehaves.

**Fonts used.** The first available bold face is picked from a candidate list
(Arial Rounded Bold, Arial Bold, Verdana Bold, Tahoma Bold on macOS;
Arial Black/Bold, Verdana Bold, Segoe UI Bold, Tahoma Bold on Windows).
Fonts are read read-only from the system; none are redistributed.

**Units.** Fusion's API works in centimetres internally; STL export of these
bodies writes millimetres.
